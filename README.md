# Practical external

Windows x64 external application with a C++ host and WebView2 interface. The source lives in `Apps/Basketball/Native`; keep this directory layout because the engine includes `Apps/Basketball/build-offsets.hpp`.

This repository contains the external source, UI, resources, diagnostics, build scripts and tests. Generated applications, packet captures, personal settings, downloaded SDKs, and the old Lua project are excluded. Previous Git history is preserved.

## Build

Install Visual Studio 2022 Build Tools with the Desktop development with C++ workload and Windows SDK, the Microsoft Edge WebView2 Runtime, and Python 3.12 for the optional network helper.

From `Apps/Basketball/Native`:

1. Run `powershell -File scripts/setup-dependencies.ps1` to fetch the pinned WebView2 SDK and create a Python build environment.
2. Run `scripts/build.cmd` to build and test the native app. It installs `Vanta.exe` and its matching release catalog into `Apps/Basketball`.
3. For the optional network helper, run `scripts/build-network-decoder-lab.cmd`, then `.venv\Scripts\python.exe scripts/build-network-host.py`. Copy the contents of `build/network_decoder/runtime` to `Apps/Basketball/network_decoder/runtime`.
4. Start the app with `Apps/Basketball/Start Vanta.cmd`.

The optional packet integration requires a compatible WinDivert 2.2 x64 runtime supplied separately through your normal approved dependency setup. Point `VANTA_WINDIVERT_DLL` at its absolute DLL path, or place the runtime beside the helper executable. Driver binaries are not distributed or downloaded by this repository. Without them, the app builds, but packet functions remain unavailable. Do not disable security software to install dependencies.

The Roblox offsets and protocol schema are version dependent. The current offset profile targets `version-4ea8e85481e34f46`; unsupported versions must pass the existing compatibility checks before features are enabled.

## Quarterback controls

First-session setup: enable QB aim once. If prompted to rejoin, keep Vanta and Roblox open. After the game loads and the connection checks pass, press Continue: QB aim resumes automatically in the same Roblox process. A prepared join listener keeps its authenticated setup in memory until Continue, avoiding a second helper launch and scan. Setup still expires after two minutes; turning QB aim off or closing Vanta cancels it and any pending resume.

Setup consumes key-scan results in short slices instead of waiting for the whole scan, while preserving the scan's total time and byte limits. Previously validated schemas are reused for their authenticated process/connection. A new connection may still require a join schema; this is not a promise of zero rejoins or a fixed startup time. The HUD says Setting up until transport is ready, separately from whether a reachable throw has been found.

Enable QB aim in the Football Fusion 3 workspace. Equip a football, wait for a ready target, and click normally. Calculated power works without waiting for the wheel. Manual game-power mode requires a valid visible display; hidden copies left by an earlier ball are ignored.

- Q locks or unlocks the selected receiver. Z cycles the pass mode; the pass card has previous/next buttons. Modes are Auto route, Bullet, Lob, Mag, Slant and Touch. Mag is an elevated touch preset; it does not expand catch range.
- Auto route searches powers from 15 through 95 in five-point steps, both ballistic arcs through 85 degrees, and reachable catch heights. Estimated-clear paths always outrank contested paths; among clear paths, higher power, shorter flight and lower elevation are preferred. Searches run at 10 Hz, with the retained trajectory recomputed for current positions between searches. In regular mode, time-based limits ease actual angle and placement changes on every planning exit, including changes between contested and clear candidates. Intermediate throws are solved again and retain their own measured coverage; they do not inherit the destination arc's clearance. If the old elevation becomes physically unreachable, the planner uses a reachable solution rather than misplacing the catch. Power hysteresis does not retain an unnecessarily weak open throw. R/F still selects manual elevation with calculated power.
- **Beam mode · adaptive power** is optional and off by default. It searches every integer power from 95 down to 1 and chooses the highest tested power with an estimated-clear, receiver-reachable path. Both roots share one solve, using derivative extrema and a conservative vertical reach bound instead of a fixed time sweep. Six vertical catch samples are tried at each power before stepping down; distant catchers are pruned only when a geometric lower bound proves they cannot change the coverage minimum. Both ballistic roots are available through 85 degrees: a lower-power high arc can replace an interceptable low beam. The old 35-degree restriction is removed. At equal clear power, Beam prefers the lowest workable angle and periodically retries the lower root rather than retaining a high arc indefinitely. When no estimated-clear candidate exists, Beam keeps the highest reachable power and favors a low arc, retaining its contested risk label; the planner does not claim a guaranteed safe throw. Beam retains the highest-power goal across planner reads. Large root/power changes must persist for 220 ms rather than following alternating candidates. Placement advances on every read instead of stepping only at the 10 Hz search rate. Reachable angle transitions are solved at up to 45 degrees per second, with transient power adjustment as needed to preserve the catch point; the selected goal still prioritizes 95. Intermediate trajectories retain their own coverage result, and a clear current throw is not replaced by an unsafe intermediate. If no valid transition exists, a valid new solution takes precedence over visual continuity. Preview geometry is not blended separately from the transmitted throw. The helper preserves the selected arc and power and rechecks coverage from the actual event origin. Changing pass type or using R/F exits Beam. The force95 setting key remains for compatibility.
- R raises the angle and F lowers it, switching to manual angle with calculated power. Power updates continuously within the game's 1–95 range; unreachable angles are reported. Cycling the pass mode restores automatic angle and calculated power. Hotkeys require the game to be focused and do not activate while typing.
- With Calculate power off, the game's visible power and the advanced Direct/Lob setting determine the throw until a pass-mode or R/F action enables calculated power again.
- Smart fit uses shared catch geometry and jump timing, with different movement assumptions: defenders may contest freely, while the receiver follows the observed route. A stationary receiver is no longer assumed to sprint or dive sideways to rescue a bad placement. Moving receivers receive only a bounded lateral adjustment around their predicted route. For supported rigs, arm, torso, head, catch-part and ball dimensions provide a shoulder-centered catch bound; unknown shapes retain conservative defaults. It reads walk speed and jump capability, removes the defender-only jump bonus, and allows jump height only as quickly as the jump can rise. The estimated dive burst replaces running during that interval instead of adding both full speeds. Catch-arm horizontal and vertical extension share an elliptical bound. Clearance is reported in studs with a one-stud uncertainty buffer. These are kinematic estimates, not server hitboxes or a guarantee; dive timing/speed and free direction changes remain modeled assumptions.
- Smart fit samples nearby placements around the observed route, including small diagonal adjustments. Additional horizontal placement can search up to 6 studs for a stationary WR, but must remain inside actual modeled catch reach rather than granting a six-stud catch radius; moving WRs retain a time-bounded maximum of 6 studs, with less adjustment on short flights; normal route lead is calculated separately. Both the app and helper enforce this limit and validate receiver reach. The full sprint/dive placement search is removed, and retained placements outside the limit are rejected. Each candidate is checked against every other catcher along the whole flight. A clear 95-power low arc skips the remaining power sweep; retained clear fits are revalidated. If no estimated opening exists, the best available valid fit remains ready for an assisted throw and is labeled contested. The helper recomputes coverage at the event origin and permits contested fits from the app, retaining the actual risk in its result. Receiver reach, route-offset limits, physics and input freshness are still validated.
- **Contested / ready** permits assisted throws while reporting predicted defender overlap. Smart fit still ranks estimated-clear paths above contested ones. **Fit unavailable** means no valid reachable trajectory or incomplete coverage; normal manual clicks remain available. **Open estimate** is a prediction, not a guarantee. Candidate launch/catch clearance is used as an optimistic bound to skip paths that cannot outrank the current choice, reducing crowded-scene search latency without skipping a potential winner.
- A physical click immediately publishes the fresh ready plan before normal game input continues. That plan remains tied to the click for at most 350 ms, even after the game removes the equipped ball. Session/character/revision changes cancel it. The helper checks file revisions on each outgoing packet instead of using a 15 ms pre-click cache. `state.json` records the last declined throw reason, and `plan.json` indicates when a click snapshot is retained.
- Preview and transmitted throws both account for the five-stud forward launch offset. The packet calculation keeps the original event origin and solves the trajectory from the resulting launch position.
- **Lead distance adjustment** is a persisted slider from -12 to +12 studs, default 0. Negative values pull the catch point back; positive values move it farther along the receiver's observed direction. Stationary receivers use the direction from QB to WR. This bias is added to normal movement lead, separately from Smart fit's bounded adjustment. Native and helper calculations agree on the signed bias; receiver reach and coverage are still checked.
- The field preview uses the same power/root or angle calculation as the helper, advancing the receiver by sample age and reading the current QB head position. It draws the complete ballistic arc to the field. A small circle marks the catch-height point; the larger field ring marks where an uncaught ball would land. It no longer presents the vertical projection of an elevated catch as the ground landing or draws a blended, non-ballistic curve. Smooth placement is solved in the planner so preview and transmitted geometry stay consistent.
- The render thread reads the camera matrix directly from the current process's already-resolved visual-engine address on every draw, instead of projecting through a matrix captured before the planner's search. Viewport position is refreshed on that thread too. This is a bounded matrix read, not another scan. Valid flight models advance to render time while preserving their fitted world trajectory. QB and ball geometry share one transparent surface/upload. A high-resolution waitable timer targets a 144 Hz loop after subtracting rendering time, replacing the fixed post-render Sleep(16). Actual render rate and work time are available as renderHz/renderMs in local plan diagnostics; this target is not a guaranteed game frame rate.

- The bottom throw capsule now uses the actual `ui/throw-hud.html` supplied from `Claudes work/vanta-ui/throw-hud.html`, hosted in a separate transparent WebView2 overlay. Its layout, CSS and phase transitions are preserved; the native backdrop is disabled for this overlay after a live blank-blur report, using the page's opaque fallback instead; the adapter supplies FF3 studs, 1–95 power and live receiver/flight data, with bundled Inter fonts instead of network fonts. Unknown distances display a dash and unknown flight coverage hides the Clean/Intable chip. No catch results are invented. The old GDI capsule is removed. Incoming native data updates the DOM and window region immediately, including while hidden; it does not depend on a suspended animation frame to become visible. Host visibility is explicitly synchronized with WebView visibility. The HUD has no taskbar button or activation, hides when the game loses focus, and does not close the main app when its own window closes.

- The current held-ball forecast takes priority over older flight/result cards. With a newly held ball and no valid plan, old cards stay hidden. The HUD follows a locally clicked pass, associated through the equipped-ball identity or its local ThrownBy reference and new-flight timing. It never picks the newest unrelated ball. The risk horizon no longer stops at an intended catch height that the receiver cannot reach. WR to spot and Nearest D use live actors and the tracked ball's projected catch position in 3D; a distant defender is not hidden behind a display sentinel. Intable evaluates the remaining ball path, height, flight time, jumping and diving, rather than copying receiver-contested status. Teamless practice players remain potential catchers, while known teammates are excluded from defender risk. Turning off all-ball trajectories does not disable own-pass HUD tracking. Before release, Intable samples the shared predicted throw against future defender reach and records the limiting flight time. That release-time forecast remains attached to the owned pass instead of becoming clean merely because the ball has passed a DB. The Intable flag requires an estimated catch-volume overlap (gap at or below zero); the planner keeps its separate one-stud clearance buffer without presenting that buffer alone as an interception.
- Catch and interception results require observed possession of the same ball, or an unambiguous newly held ball carrying the local thrower reference near the last observation. Known teammates/selected receivers show Caught, known opponents show Intercepted, and unknown teams remain explicitly unknown. Observed descending ground contact shows Incomplete. Disappearance alone shows Result unavailable. Results remain visible for 2.6 seconds and are logged once in the local QB event log. The tracker clears across character/session changes.
- Live settings snapshots cannot overwrite a pointer-owned slider drag or an active value-box edit. A released slider retains its committed value while waiting for native acknowledgment, with a bounded timeout; cancel/lost-pointer-capture also completes the drag.

- **Catch height adjustment** ranges from -3 to +8 studs in both regular and Beam modes. It shifts the preferred catch height; Smart fit can raise it further within measured receiver reach. The setting persists and uses the same drag protection as lead distance. A locked receiver remains selected when the camera moves off-screen. Regular and Beam remember independent height/lead settings. Beam defaults to +8 studs of height and +3 studs of lead; changing regular mode does not overwrite those values. Old settings migrate without changing regular-mode values.
- Beam presentation may retain geometry for up to 300 ms while a search finishes, reprojected against the current camera. A matching held-ball/target preview bridges an invalid planner result for at most 180 ms; it clears on release, target change, text focus, session or setting changes. The five-stud spawn offset is included in the displayed ballistic solve; this does not relax the separate 100 ms click freshness limit. The sender advances moving targets by the measured sample and dispatch delay, and extends catcher reach horizons by that delay too. Normal input still passes through if an assisted plan is unavailable.
- The read-only movement probe reports configured walk speed, jump mode/power/height, catch dimensions, and observed horizontal/vertical speeds. Current practice observations were walk 20, jump power 50, gravity 196.2 (6.37-stud rise), and horizontal bursts up to about 43.5 studs/sec. Stationary route filtering ignores sub-1.5-stud/sec velocity/position noise so bot jitter does not reverse lead direction. Receiver targeting and both solvers now accept horizontal movement through the shared 45-stud/sec model bound, so observed dives are not rejected by an obsolete 40-stud/sec limit. Dive distance remains a configurable estimate; these observations do not establish every possible game movement or guarantee interception-free throws.
- **Live ball trajectories** works independently of QB aim and tracks up to 64 visible workspace footballs. A gravity-aware spatial parabola fits at least seven position samples spanning 0.3 seconds and eight horizontal studs. Horizontal progress, rather than variable replication arrival times, determines the curve and velocity. Nearly vertical or insufficiently sampled flights wait for a valid fit. A model is held while observations agree with it, keeping its landing fixed despite stepped replication; sustained disagreement or a large jump discards the forecast and waits for a new fit. Each flight retains its field height to prevent foot-animation noise from moving the landing. The overlay draws the whole fitted world-space arc to its predicted field intersection with a landing ring. Its path does not move forward from the ball tip; no raw tip-following trail is drawn while a forecast is unavailable. QB beams use a violet core and flight forecasts use cyan, while ground markers retain coverage colors. Rings are batched paths instead of dozens of individual draw calls. The forecast assumes the measured gravity and no intervening collision; unknown gravity or field height suppresses the forecast. Catch/reparent/removal, reaching the field while descending, observed impact, rest/rolling or timeout clears the visualization. This is a prediction, not a perfect server trajectory or map raycast. Tracking does not start the packet helper.


## Validation and collaboration

`build.cmd` runs the native tests. `powershell -File scripts/check-qb-hud.ps1` checks the actual HTML capsule in an isolated overlay and saves aim/flight previews without game input. `powershell -File scripts/check-webui.ps1` runs an isolated WebView test without live input hooks. With the Python environment active, run `python -m unittest discover -s build/network_decoder -p test_*.py` for the decoder tests; run the network helper build first so the test directory contains the scanner DLL.

Clone this repository to a fresh directory, create a branch for your changes, and use pull requests into `main`. Commit source and tests, not builds, local settings or captures. Third-party code retains its own license notices; the WinDivert header's license notice and the UI fonts' OFL are included.
